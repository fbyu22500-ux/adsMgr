# FB 广告账户管理系统 · 本地运行说明

单文件前后端（`server.py` + `index.html`）+ JSON 数据，**Python 标准库即可运行**；仅「Excel 批量导入 / 模板下载」需要 openpyxl。版本 **v3.10**（安全加固 + 行内状态修改 + 表头筛选修复 + 一键安装环境）。

## 一、三步上机清单（小白版）
1. **解压本包**（保持文件夹完整，不要只拖单个文件出来）
2. **双击一键安装**：Windows 双击 `安装环境.bat`；Mac 双击 `安装环境.command`
   —— 自动装好 Python 与 Excel 组件（需联网，约 1~3 分钟），装完自动打开浏览器进入系统
   —— Mac 若弹“Apple无法验证…”（对下载文件的一刀切拦截）：二选一放行——
      ① 终端执行一行：xattr -cr ~/Downloads/FB广告账户管理系统
      ② 系统设置 → 隐私与安全性 → 安全性区域 → 【仍要打开】
      （详细步骤与替代方案见「!先看这里-安装说明.txt」）
3. **登录 `admin / admin123456` → 立即改密码**（右上角头像菜单，密码 ≥6 位）

> 以后每天使用：Windows 双击 `启动.bat`，Mac 双击 `start.command`（不会再装环境）。
> 没看懂？包里第一个文件「**!先看这里-安装说明.txt**」就是给第一次使用的人写的。
> 手动党：`python server.py 8765`（端口占用换 `python server.py 3000`）。

## 二、环境要求
- Windows / macOS / Linux；Python 3.8+（语法已按 3.8 校验通过）
- 基础功能零第三方依赖；可选：`pip install openpyxl`（仅 Excel 导入 / 模板下载需要）
- 数据、凭证图片、日志全部在本目录 `data/` 下，不写注册表、不联网（除你主动配置的邮箱备份）

## 四、重要业务规则（数据链）
1. **先下户，再充值/投放**：下户表「客户 + 账户ID」必填；BM 消耗导入按**账户ID + 消耗日期**匹配下户归属段，未登记的 ID 拒绝导入并列出清单；Excel 媒体与归属段媒体不一致也拒绝（系统设置可整体关闭该校验；段媒体留空=不设限）。
2. **转户（广告户按日期换客户）**：旧段「结束日期」填转出日，次日起新增新段即可。历史消耗按**消耗日期**归属当时客户；日期落在两段之间的**空窗期按系统设置「空窗归属」规则处理（默认归前一段=转户语义，可切回归尾段=旧行为）**。两类区间外消耗都会留痕：日消耗明细里分别标 `⚠️ 超出归属期` / `⚠️ 早于下户期`，导出同名字段，弹窗汇总提示天数。充值按**充值日期**归属对应期间客户。
3. **账户状态（三态，两个入口同规则）**：录入表单的「账户状态」下拉，以及**充值明细行内的「状态」下拉**（v3.9）都写到该账户「充值日期命中的下户归属段」上，充值流水不冗余存状态；因此改一次，该段所有充值行与按账号汇总徽标同步。账户未登记归属段时会被拒绝并提示先去「下户表」登记。录「清零」金额时下拉自动变清零；重新启用时录一笔充值并把状态改回「正常」。录「清零」时账户状态下拉自动变清零；重新启用时录一笔充值并把状态改回「正常」。（账户状态写回充值日期命中的归属段，操作留痕。）
4. **四个"余额/备款"公式（表头悬停可看）**
   | 名称 | 位置 | 公式 |
   |---|---|---|
   | 充值净结余 | 首页指标卡 💎、日消耗弹窗 💵 | 累计充值 − 累计清零 − 累计消耗 − 累计服务费 |
   | 净备款 | 打款管理 🏦、备款一览（客户维度） | 累计打款 − 累计退款 −（累计消耗 + 累计服务费） |

独立服务费可在左侧「服务费」栏目按客户单独维护，仅在数据概览的「备款明细」中作为额外扣款展示，不计入 Hero、账号/客户汇总、备款一览或其他导出表。
   | 广告账号余额 | 按账号汇总末列 | 该账户累计充值 − 累计消耗（不扣清零与服务费；负数=该户投放已超出充值）|
   | 投放结余 / 差额 | 充值清零 → 账号对账 | 投放结余 = 累计充值 − 累计消耗；差额 = 投放结余 − 累计清零 |
   另：充值明细的「账户结余」= 该账户累计充值 − 累计清零；「客户净备款」列同客户维度口径。全站备款一律以「打款 − 退款 −（消耗+服务费）」为准，充值/清零只作流水展示；允许为负（赊账，红色警示）。打款按客户池→(消耗+服务费)占比分摊到账户，尾差归最大条目，保证分项合计=打款池。
5. **退款 ≠ 终止客户**：现金退款只是「某笔打款打多了要退回」，不改客户状态、不屏蔽下拉，同一客户可反复退款；「剩余备款 = 累计打款 − 退款 −（消耗+服务费）」；超出会二次确认。
6. **转账凭证（截图）**：打款/退款每行右侧「📎」→ 上传 png·jpg·gif·webp 转账回单（**按文件头校验**，改扩展名无效；单张 ≤8MB、单笔 ≤12 张），支持多选与拖拽；新增表单可先选图、保存后自动挂到该笔账。图片仅经带登录态的 `/attachments/...` 路由读取（`data/` 禁止静态直读）；删除凭证/记录/清空会级联清理文件；导出 Excel 含「凭证张数 / 凭证文件」。
7. **删除权限**：打款、退款的**删除**（含凭证删除、清空打款）仅**管理员与财务**（权限位 `can_delete_money`，后端强校验，前端只作展示收口）；删除即金额回退——累计打款/累计退款/分摊/备款一览/按日期汇总/可退备款全部按剩余记录自动重算，不留差值。
8. **权限中心**（仅管理员）：账号可分配 ①可见导航模块 ②数据展示范围（客户/媒体/渠道；客户角色=绑定客户 ∪ 勾选客户）③渠道数据屏蔽（勾选或客户角色自动：隐藏渠道列/筛选/渠道数/客户×渠道页签，**导出同样剥离**）。打款管理、退款管理的**表头「客户🔽」**与筛选条客户下拉双向同步（v3.9 修复了此前「点了没反应」的死筛选；退款的财务影响合计随筛选重算）。
   导出另受「允许导出数据」权限控制（权限中心勾选，默认跟随角色；客户角色默认不可导出）。所有列表接口在服务端按范围过滤后再返回，抓包拿不到越权数据。
9. **筛选交互（全站一致）**：区间查询放在「汇总透视」标题右侧（含 近7天/本月/全部 快捷键）；下户表、充值清零、打款管理均在**表头正上方**提供「搜索 + 账号/客户下拉 + 结果计数胶囊 + ⟲重置筛选」，账号筛选同时驱动本子模块的多张表；新增记录后自动清筛选并定位高亮新行。
10. **导出**：「📤 导出全部 Excel」= 数据概览全部透视表（按账号/按客户/媒体×渠道/客户×渠道/按日期/备款一览/账号对账/日消耗明细）+ 下户表/充值清零/打款记录/退款记录，均按当前账号权限过滤；各模块另有单表导出。日期列倒序、金额分位取整可加，与界面所见一致。
11. **安全（v3.8 加固）**：请求体上限 16MB（超限 413 并断连，防内存 DoS 与请求走私）；编辑接口**字段白名单**（外部无法注入 id/createdBy/attachments 等内部字段）；全站输出转义（含下拉 `<option>`），杜绝存储型 XSS；`data/` 禁止静态直读、路径穿越已拦截（含备份包内路径校验）；`/api/auth/roles` 需登录；会话 7 天过期 + 登录时回收 + 上限 500；`save_json` 唯一临时名 + 写锁 + fsync；接口异常统一 500 JSON，不外泄堆栈；`Vary: Accept-Encoding`；脚本/API 裸请求被拒（需浏览器标识）；每 IP 600 次/分；登录 5 次失败锁 15 分钟；上传 50MB 上限；备份包排除会话令牌、SMTP 授权码在包内自动掩码。
12. **操作记录**：所有数据变更留痕（谁、何时、改了什么、登录/登录失败 IP），系统设置可查最近 2000 条。

## 五、数据备份与迁移
- **本机备份**：`data/backups/` 自动保留最近 3 份 zip（含业务 JSON + **转账凭证图片**）；恢复入口：系统设置 → 数据维护 → 「📥 恢复备份」（先暂存、输入当前密码复核、恢复前自动打安全快照，可回退）。
- **定时邮箱备份**：系统设置 → 选邮箱服务商自动填 SMTP → 填发件邮箱与**授权码** → 收件邮箱（逗号分隔）→「✉️ 发送测试邮件」→「保存设置」，并按每天/每周一 + 时间启用。（早期版本因中文附件名报错导致发送失败，v3.8 已改为 ASCII 附件名。）
- **换电脑**：系统设置 → 数据维护 → 「⬇️ 下载全量迁移包」，到新机器装 Python → 启动 → 登录 → 恢复备份；或直接整个文件夹拷走（含 `data/`），也可手工替换 `data/*.json` + `data/uploads/` 后重启。

## 六、故障排查
| 现象 | 处理 |
|---|---|
| 页面像旧版（列名/按钮不对） | 左下角确认版本号，Ctrl+Shift+R 强刷 |
| 端口被占用 / 起不来 | `启动.bat 3000` 换端口；`data` 目录需可写 |
| Excel 导入报「需要安装 openpyxl」 | `pip install openpyxl`（不影响其他功能） |
| 点保存/删除没弹系统对话框 | 已内置应用内确认框（不依赖浏览器原生弹窗，iframe 内也可用）|
| 邮箱备份失败 | 检查授权码（非登录密码）、端口 465(SSL)/587(TLS)、收件人拼写；用「✉️ 发送测试邮件」定位 |
| 客户/受限账号看不到渠道列 | 正常：勾了「屏蔽渠道数据」或客户角色自动屏蔽，导出也会剥离 |
| 恢复后 SMTP 授权码为空 | 有意为之：备份包内授权码被掩码，本机密码只在本地保留 |

## 七、已知限制与建议
1. 内嵌 HTTP 服务适合**本机/内网**使用；上公网务必套 HTTPS 反向代理（nginx/caddy）并改强密码。
2. 单文件前端保留 `script-src 'unsafe-inline'`（大量内联事件所需）。如需彻底收紧要改事件委托 + nonce，属较大改造。
3. 备份包内含 `users.json`（口令为 pbkdf2 哈希，不含明文、不含会话令牌）。若担心账号表外流，可改为默认排除 `users.json`。
4. 凭证图片会持续增长（单张 ≤8MB、每笔 ≤12 张）；`data/uploads/` 需与 JSON 一起纳入你自己的异地备份。
5. `data/` 是唯一权威数据源，建议每周至少手工下载一次全量迁移包异地留存。
